# Start building

Suppose you want a workshop where visitors can open a cupboard, find a key, and meet a cat. Start
with the place and its objects. You can add their responses after you have somewhere to try them.

A **room** is a place people can visit. A **passage** joins rooms. An **area** groups rooms and
controls who can build there. Objects such as keys and cupboards occupy rooms or sit in someone's
inventory.

You make an object from a **prototype**: an existing object that supplies its basic abilities. For
example, a container already knows how to hold things. You give your own container a name and
description, then choose how it behaves.

Building requires builder privileges and permission to change the objects or places involved. Each
lesson explains what you need before you start.

## A route through the lessons

1. Learn about [names and aliases](names-and-grammar.md). Give your objects names that people can
   recognize and use in commands.
2. [Build a workshop](rooms-and-passages.md). Connect rooms, describe their exits, and add a keyed
   door.
3. [Make a cupboard respond](../behaviour/reactions.md). Add a message when someone opens it, then
   try conditions and remembered state.
4. [Write messages](../behaviour/pronouns-and-messages.md) that name the people and things involved
   in an action.

The workshop lesson is also an automated test. It checks that its main walkthrough works for a
builder without programmer privileges.

## What still needs a chapter

The book needs an introduction to the supplied objects: containers, clothing, food, seats, and
notes. It also needs a description-writing guide and a complete shared-building lesson.

Some of those topics already appear inside longer tutorials. The planned chapters will explain them
together, including how ownership and grants affect work on someone else's area.
